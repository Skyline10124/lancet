# ADR 0003：影子中的 Git：普通进程与按文件发布

## 背景

### 来源

- [ADR 0002 第 6 节](0002-lancet-node-api-tools-and-act.md#6-影子工作区待定改动与发布)为影子配了一个私有的 `.git/`，内容是宿主 HEAD、index、refs 与 config 的副本，对象经 alternates 只读借用宿主的 `.git/objects`。发布时，节点再把引用与 index 写回宿主。
- 2026-11-20 至 2026-11-21，[#7](https://github.com/Skyline10124/lancet/issues/7) 的切片 4c 在实施前做了验证，之后又做了三轮实验与三次独立审查，发现下表中的问题。维护者据此暂停原设计，实施并入 [#8](https://github.com/Skyline10124/lancet/issues/8)，排在执行环境之后。本 ADR 记录新的设计。

### 要解决的问题

| 问题 | 证据 |
| --- | --- |
| `hidden` 经宿主对象库泄漏 | 主 Agent 在 Git 2.52.0 上按原设计建库，测出五条泄漏途径：<br>- 私有 index 列出被跟踪的 `hidden` 路径；<br>- `git show HEAD:<路径>` 读出内容；<br>- `git log -p` 读到已删除文件的历史内容；<br>- 撤出暂存后留下的悬空 blob，经 `git fsck --unreachable` 可以找到；<br>- `git stash -a` 会收进被忽略的文件。 |
| 为 Git 单独设计的写回宿主机制收不拢 | 三次独立审查依次提出 9、6、11 条阻塞，大多来自两处：在 4b 之外另做一套 Git 事务；Git 状态与用户的检出相互耦合 |
| 节点在沙箱外对 agent 的仓库运行 git，会执行该仓库配置的命令 | 实验中的实测：<br>- `git status` 与 `update-index` 会调用 `core.fsmonitor` 和 `post-index-change`；<br>- `update-ref` 会调用 `core.hooksPath` 下的 `reference-transaction` |
| 其他位置的 `.git` 原样可读 | 只读目录的路径规则不保留 `.git`；工作目录中的嵌套仓库，会作为常规路径复制进影子 |

### 维护者的要求

以下要求由维护者于 2026-11-20 至 2026-11-21 提出：

- 两种场景都要支持：
  - 在用户当前的工作树上改动，完成后整批落回；
  - 交付分支。
- `hidden` 不降级，承诺的口径与 `fs.*` 相同。不接受“只保护从没进过 Git 的内容”。
- 沙箱里要能使用原生的 git，以及依赖它的 `gh` 等工具链。
- 不另做 Git 事务：git 就是普通的进程，`.git/` 当普通文件，交给现行的发布事务（下称 4b）发布。

### 已核实的事实

除另有注明外，以下事实于 2026-11-20 至 2026-11-21 在开发主机上核实。环境：Git 2.52.0，Linux 6.12，XFS，8 个 vCPU。合成仓库有 10 万个已跟踪文件、约 3,000 个提交。

| 事实 | 核实方式与结果 |
| --- | --- |
| 过滤投影能隔离宿主对象 | SHA-1 与 SHA-256 各验证一次：<br>- 私有对象库的全对象枚举，与投影的可达闭包完全相等；<br>- `hidden` 的名字与内容命中 0 次；<br>- 宿主的 stash、悬空对象与 reflog 都不可读。<br>独立审查用 `mktree` 复核，结论一致 |
| `.git` 当文件交给 4b 发布，宿主仓库保持一致 | 历史干净的仓库，SHA-1 与 SHA-256 各做五种操作后发布，共 10 次：<br>- 宿主 `fsck --strict` 全部通过；<br>- 与本批无关的暂存保留，reflog 字节不变；<br>- 影子执行过 `gc` 时，宿主只增加本次提交所需的对象 |
| 锁内的并发 | 节点持有 `index.lock`、`HEAD.lock`、相关引用锁与 `packed-refs.lock` 期间：<br>- 宿主的提交、切分支（包括切到本批要更新的分支）、暂存、刷新 index、`pack-refs` 都返回 128 并被挡住；<br>- 节点取锁之前发生的这些变化，取锁之后的复核都能发现。<br>只持目标分支锁时，宿主仍能切过去，结果 HEAD 指向新提交，index 与工作文件却是旧的 |
| 整批全有或全无，可在崩溃后恢复 | 引用文件与普通文件同批：<br>- 晚到的冲突可以按 4b 逆序撤回；<br>- 进程被 `SIGKILL` 的三个磁盘现场，都能由新实例按日志恢复；<br>- 撤回之后，已装入的新对象成为悬空对象，`fsck --strict` 仍然通过。<br>未做断电测试 |
| 历史里有 `hidden` 的仓库可以翻译 ID | 推进当前分支、推进已有分支、新建分支，三种情形都能把投影 ID 翻译成宿主 ID：<br>- 宿主上是真快进；<br>- 映射结果再投影，等于 agent 的提交。<br>锚点只看投影图会出错：两个投影相同的宿主父提交，往返核对都能通过，宿主上的祖先关系却一真一假 |
| 往返核对能发现断链被补活 | 宿主父提交里有被剔除的断链 `alias -> asset`，agent 新建了 `asset`，往返核对发现补回后多出了 `alias` |
| 准备 index 时可以不碰宿主 | 只把 `GIT_INDEX_FILE` 指向私有副本时，宿主 `sharedindex.*` 的 mtime 仍然变了。改为把 index 与共享文件复制进节点私有的 gitdir 后再准备，宿主 `.git` 的 37 个条目没有任何变化 |
| 三处不能按原样复制或比较 | - 直接复制宿主 index：只被宿主暂存引用的 blob 不在闭包里，影子的 `fsck` 与 `gc` 报对象缺失。<br>- 投影后的 `packed-refs` 整个文件写回：宿主的 `refs/stash` 等未暴露记录会消失。<br>- 只按完整路径核对暂存：宿主暂存了 `d/x`、影子把 `d` 提交成文件时，用户的暂存会悄悄消失 |
| 成本（Python 加 git 命令行的原型） | - 历史干净时建影子 `.git`：973 ms；<br>- 发布 1 个提交，`.git` 部分 195 ms；发布 100 个提交，250 ms；<br>- 启动时扫描暴露历史，判定有没有 `hidden` 路径：2.7 s。<br>gix 原型：增量投影约 2 ms，映射 1 个提交约 3 ms |

## 决策

### 1. git 是普通进程，`.git/` 按普通文件发布

- **影子里的 `.git/` 归 agent 使用。** agent 在执行环境中原生运行 git。`commit()` 时，`.git/` 的改动与其他文件改动在同一批里，由 4b 发布。
- **按文件发布时的四条专用规则：**
  1. 引用、HEAD 与 `packed-refs` 当文件发布，内容翻译成宿主 ID（决策 3）；
  2. 对象只发布新增的，在节点私有的 gitdir 中校验之后装入；
  3. 宿主 index 不按文件发布，而由节点准备后态（决策 4）；
  4. `config`、`hooks/`、`info/` 与 reflog 从不发布。
- **查看待定改动：** `status()` 与 `diff()` 把 HEAD 与引用的变化列为 `.git/HEAD`、`.git/refs/...`，这些项计入待定提示。对象、index、reflog 不列出。
- **丢弃：** `discard()` 把这些文件恢复到基准，并按投影 HEAD 重建私有 index。

### 2. 影子 `.git/` 的建立与同步

- **投影：**
  - 宿主提交的树里有“投影时隐藏的项”时，删去这些项，父提交随之改写。这类项见决策 5。
  - 投影提交与宿主提交的序列化相同时，沿用原 ID，所以历史干净的仓库，投影就是原样。
  - 只改了这类项的提交，投影后成为空提交，予以保留。
- **对象库：** 只放从暴露的分支与 tag 可达的投影对象，以 pack 写入，不用 alternates。宿主的 stash、悬空对象与 reflog 都不进入。
- **引用：**
  - 暴露宿主的本地分支 `refs/heads/*` 与 tag `refs/tags/*`。
  - `HEAD` 照宿主的设置。
  - 远端跟踪引用、stash、notes 与 replace 引用都不导入。
- **私有 index：** 由投影 HEAD 的树建立，不复制宿主 index。
- **生成的文件：** `config`、`hooks/`、`info/` 由节点生成。
- **同步：**
  - 引用文件与 HEAD 照 4a 的规则逐个同步：影子里没有改动的项随宿主更新，写入投影后的 ID；有改动的项保留，宿主也改了就标冲突。
  - 每次 `act` 开始时，比较宿主的 HEAD 与引用，对宿主的新提交做增量投影。
  - HEAD 随宿主切换时，私有 index 若没有 agent 的改动，按新的投影 HEAD 重建。
- **仓库分类：**
  - 启动时扫描暴露的历史，判定其中有没有 `hidden` 路径；宿主有新提交时做增量判定。
  - 分类结果只用于决策 4 的“切换 HEAD”一条。

### 3. 映射回宿主：ID 翻译

- **锚点：** 已有分支以宿主上该分支的真实 OID 为锚点，这个 OID 在节点取锁之后复核。agent 的新提交必须从锚点的投影长出来，否则整批拒绝。
- **映射：** 按父先子后的顺序，把新提交映射回原历史：
  - 从锚点或已确定的宿主父提交补回“投影时隐藏的项”，并保留锚点原有的 `hidden` 项；
  - 检查文件与目录的冲突；
  - 映射后的提交必须在宿主图上从锚点快进。
- **往返核对：** 每个映射后的提交再投影一次，必须与 agent 的提交相同。
- **新分支：** 起点必须是某个暴露分支当前值的投影，或者是同批中已经映射过的提交；其余情形无法确定来源，整批拒绝。
- **多父提交：** 逐个父提交核对来源。
- **写入：** 宿主的引用文件写入翻译后的宿主 ID。`packed-refs` 以宿主的原文件为底，只合入暴露引用的变化，未暴露的记录原样保留。
- **不发布的引用操作：** 删除分支、新建或修改 tag 都不发布，回执写明。

### 4. 发布

- **锁：** 凡是批次里有 `.git/` 改动，初检之后都按下列顺序取锁：
  1. `index.lock`；
  2. `HEAD.lock`；
  3. 当前分支与各目标引用的 `.lock`；
  4. `packed-refs.lock`。

  锁文件的身份在取锁之前写进 `Undo`。取齐之后，复核三项：HEAD 的符号目标与解析出的 OID、各引用的前态、index 的前态。锁一直持有，跨过交换、撤回直到 `Finish`。
- **切换 HEAD：** 影子的 HEAD 改指另一分支时，历史干净的仓库照常发布这次切换；历史里有 `hidden` 路径的仓库整批拒绝。拒绝的依据是决策 2 的仓库分类，不看具体状态。
- **宿主 index：** HEAD 的提交变了时，节点在私有 gitdir 里准备宿主 index 的后态，作为普通文件交给 4b 交换：
  1. 把宿主 index 与它的共享文件 `FICLONE` 进私有 gitdir，展开成完整的 index；
  2. 按新旧两个 HEAD 树的差异，用 git 只更新本批路径；
  3. 核对本批路径在宿主上没有暂存；
  4. 核对本批以外的条目全部不变。
- **你在影子里的操作就是最终结果：** agent 在影子里移动你未提交的改动，例如提交到 topic 再切回 main，发布结果与它直接在你的检出里做同样的 git 操作相同。回执中的 diff 列出被改回 HEAD 版本的文件。

### 5. `hidden` 的承诺

- **承诺：** 节点不把以下内容带进沙箱，口径与 `fs.*` 相同：
  - `hidden` 的树项；
  - 只能经由这些树项到达的对象；
  - `hidden` 路径的名字与状态。
- **投影时隐藏的项：**
  - 匹配 `hidden` 的路径；
  - 目标经过 `hidden` 位置的符号链接；
  - 越界、断开或成环的符号链接。

  符号链接按它所在提交的树判定，与 `fs.*` 的 `entries` 相同；物理影子同样剔除这些链接。
- **已跟踪的 `regenerable` 文件：** 在投影中可见。任一待发布的提交改动它们，整批拒绝。同时匹配 `hidden` 时，按 `hidden` 处理。
- **只看规则就拒绝的情形：** 下面两种情形，节点只依据规则与 agent 可见的内容判定：
  - 新建匹配 `hidden` 的路径；
  - 在规则上可能波及隐藏后代的结构变化。
- **明确的例外：** 下面四条的成败取决于宿主的隐藏状态，每条只透露“这里有不可见的东西”这一位信息。合同逐条写明，报错不给出名字、链接目标与宿主的 ID：
  1. 新建的路径与不可见的链接撞名；
  2. merge 的几个父提交补回的受保护状态不同；
  3. 往返核对失败，例如断开的链接被补成了有效链接；
  4. 历史里有 `hidden` 路径的仓库，不发布 HEAD 切换。这一条透露了仓库属于哪一类。
- **不在承诺范围内：**
  - 用户写在可见处的内容，包括可见文件、提交说明与分支名；
  - 空提交暴露的改动时间点；
  - 与某个可见文件字节相同、因而共用 blob 的 `hidden` 文件。
- **回执：** 只给出投影里可见的信息。回执写投影 ID，不写宿主 ID；装入的对象只写数量。宿主 ID 只记在不挂进沙箱的发布日志里。

### 6. 事务、恢复与并发

- **一笔事务：** 引用、HEAD、`packed-refs`、宿主 index 的后态、锁文件与普通文件，都在 4b 的同一笔事务里，日志沿用 `Undo` 与 `Finish`。新对象在临界区里最先装入。
- **原子范围：** 引用、index 与工作文件的最终状态全部生效或全部不生效。保证表写明两个例外：
  1. 撤回时宿主又改了已发布的项，保留宿主的修改，这是现行规则；
  2. 已装入的对象不撤回，撤回后可能成为悬空对象。
- **恢复：** 只删除身份与登记相符的锁，不写宿主的 reflog。
- **并发：** 只承诺已经验证的部分：节点持锁期间，宿主上的 git 操作都会被挡住；取锁之前发生的变化，复核时都能发现。另外写明：在节点取锁之前就已开始、发布结束后才继续执行的 git 进程，例如一个很慢的 `git switch`，不在保证范围之内。

### 7. 节点读取 agent 仓库的边界

- **不作为输入：** 私有仓库的 config、hooks、alternates、replace 引用、grafts 与 shallow 边界。节点不对私有仓库运行 git 命令行。
- **读引用：** 引用、HEAD 与 `packed-refs` 经不跟随链接的目录 fd 读取，按字节解析。
- **读对象：** 映射需要对象时，等沙箱里的写者全部退出，节点把 loose 对象和成对的 `.pack`、`.idx` 用 `FICLONE` 复制进自己新建的读取视图。视图的 config 由节点生成，用 gix 打开；视图用后删除。
- **宿主一侧：** 节点信任宿主仓库，在宿主一侧调用 git 命令行，用于打包、校验对象、准备 index 后态。这些调用都关闭 hooks。

### 8. 挂载与 `.git` 的保留

- **私有 `.git/`：** 单独挂载，跨挂载建硬链接会返回 `EXDEV`。宿主的 `.git/objects` 不再挂入执行环境。
- **任意深度的 `.git`：** 指嵌套的仓库与 gitfile。它们不进物理影子，`fs.*` 不可见，也不发布。工作目录根下的 `.git` 按决策 2 处理。
- **只读目录：** 只读目录中的 `.git`，在执行环境中以同类型的空项遮蔽；`fs.*` 同样保留它。

### 9. 支持范围与性能

- **第一个版本支持：** 工作目录是仓库根；引用为 files 后端；对象为 SHA-1 或 SHA-256。
- **不启用 Git：** 以下情形只提供文件能力，启动时警告并写明原因：
  - 暴露的历史里有 gitlink；
  - 根下的 `.git` 是 gitfile、符号链接或无效的。
- **待实施时验证：** reftable、登记了其他 worktree 的仓库。验证通过后再放开。
- **推迟：** 子目录根推迟到第一个版本之后，子目录照现状按普通目录处理。
- **性能：** 原型中，发布 1 个提交时 `.git` 部分的耗时，已超过“单文件发布中位数不超过 50 ms”的验收线。5c 用 Rust 实现后重测；仍然超线时，交维护者决定。

### 10. 依赖

| 依赖 | 用途 | 版本与特性 | 不用现有依赖的理由 |
| --- | --- | --- | --- |
| gix | 在进程内投影与映射回宿主，读取节点生成的读取视图 | `=0.85.0`，`default-features = false`，只开 `sha1`、`sha256`、`index` | 现有的 `ignore` 只判定路径规则，`sha2` 只算摘要，都不能解析对象库、pack 与 index |

## 否决的方案

| 方案 | 否决理由 |
| --- | --- |
| ADR 0002 的私有 `.git/`：经 alternates 借用宿主对象库 | `hidden` 经五条途径泄漏，见背景 |
| 把宿主的 `.git` 只读挂进执行环境 | 理由同上；宿主 config 中还可能有带凭据的 remote URL |
| 沙箱里不提供 Git | 失去 `gh` 等整条依赖 Git 的工具链 |
| `hidden` 只保护从没进过 Git 的内容 | 维护者否决 |
| 只为历史干净的仓库启用 Git | 配置了 `hidden` 的仓库，往往正是敏感文件进过 Git 的仓库 |
| 在 4b 之外另做一套 Git 事务：手写或交给 `git update-ref` 的引用事务、交付远端、分支工作区 | 三次独立审查的阻塞大多来自这里。`git update-ref` 事务被杀时，会留下半批引用与残留的锁 |
| 只持目标分支锁 | 宿主仍能切到该分支，结果 HEAD 指向新提交，index 与工作文件却是旧的 |
| 投影图上的锚点；单值反查；merge 一律取第一父 | 都有丢失宿主状态的反例 |
| 复制宿主 index；`packed-refs` 整个文件写回；只按完整路径核对暂存 | 分别会缺失只暂存的 blob、丢掉未暴露的引用、悄悄抹掉用户的目录暂存 |
| 节点在沙箱外对 agent 的仓库运行 git，再用 `-c` 覆盖配置 | 这是黑名单做法，危险配置的范围会随 Git 版本变化 |
| 只用 gix 的 isolated 选项直接打开 agent 的仓库 | 仍会解析 alternates，也会采用 shallow 边界 |
